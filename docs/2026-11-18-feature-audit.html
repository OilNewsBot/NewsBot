Newsstream feature audit

60 findings across 7 product areas. 8 high priority · 33 medium priority · 19 low priority.

High priority covers lost news, unexpected data sharing on a hosted instance, misleading trade provenance, and explicit limits that can be exceeded. Medium affects a core action or its result. Low covers recoverable friction and presentation.

Where to start

  • Keep accepted news recoverable. A restart can strand the item being classified and discard the queue. A reconnect can skip alerts, and unfiltered stories disappear from visible history.
  • Honor X limits and retrieve complete timelines. The official adapter overshoots a one-read cap and skips older posts in a 30-post burst.
  • Clarify what the trading page shows. Users can mistake a manually seeded example for a model recommendation and a shared portfolio for their own private balance.

Test coverage and limits

Six exploratory QA agents and the coordinating agent tested the fetched main-branch snapshot in isolated copies with disposable accounts, SQLite databases, browser profiles, and loopback services. The shared working checkout was behind this revision. The unmerged forum-directory overhaul was outside this snapshot.

Chromium sessions covered registration, sign-in, account switching, source filters, alert acknowledgment and backfill, portfolio entry, chart selection, keyboard navigation, mobile widths, service-worker offline recovery, and seeded history. A freshly built Windows Tauri release was exercised in WebView2. The ordinary remote path opened the real NewsBot sign-in screen.

Observed working flows included unique-username registration, source pause/resume/mute/remove, hiding removed-source history, persistent dashboard sound settings, Escape-to-dismiss, and a standard portfolio save/reload. Seeded or intercepted data, clocks, delayed responses, network failures and permission doubles are identified in each finding.

The repository’s offline check completed, including 99 Jac tests and the web build. Additional checks passed for the native mobile backend (7), mobile client (typecheck and 9 tests), Web Push transport (3), and PWA worker/manifest (3). Exploratory findings cover scenarios beyond those successful checks.

Provider-dependent cases used the real app logic with recorded or simulated inputs. No live X or Telegram feeds, paid model calls, brokerage activity, physical iOS/Android delivery, or live browser push service was exercised. Mobile browser widths and mobile controller tests cover different behavior. Findings describe this revision and the listed conditions.
